# 项目整理计划

## 目标
整理 CALIPSO_Code_new 的目录、路径、入口和文档，确保后续优化和科学修正可复现。

## 文档规则

- `TODO.md` 只记录未完成事项，不放详细步骤。
- 每个独立阶段在 `plan/` 下建立单独计划文件。
- 原有记录文件可以重写、合并、移动或删除；只保留对项目有价值且结构清晰的内容。
- 重组前先建立文件清单，确认不会误删代码、输入数据或有效结果。
- 运行结果统一放入 `result/<run_name>/images`、`blocks`、`logs`。

## 现有记录处理

- 项目说明：`docs/project/REASONIX.md`、`docs/project/function_summary.md`、`docs/project/CHANGELOG.md`
- 历史任务记录：`8 Draw AOD/task_log_20260524.md`（待后续归入 docs/history）
- hdf2mat 记录：`hdf2mat/work_log.md`、`stage0_report_20260728.md`、`stage1_report_20260728.md`
- hdf2mat 计划：保留 `hdf2mat/plan_hdf2mat.md` 等已有技术记录，并与 `plan/` 下的执行计划互相引用

## 总体原则

1. **代码可运行优先**：每次目录或文件调整后，都要用 MATLAB 做最小启动测试和基线测试。
2. **结构清晰其次**：允许大幅调整目录、文件名和文档组织，不受原目录布局限制。
3. **可恢复操作**：待确认的旧文件先移入归档目录，验证通过后再删除。

## 执行步骤

1. 建立目录清单和文件分类表，区分代码、输入数据、结果、日志、计划和归档。
2. 比较原始函数与 `_1` 版本，确认保留版本。
3. 归档 `.asv`、`.bak` 和过期实验输出，不直接删除原始数据。
4. 统一路径配置和入口说明。
5. 重写并合并有价值的说明文档，形成清晰的项目说明、计划、工作日志和变更记录。
6. 更新 `docs/project/REASONIX.md`、`docs/project/CHANGELOG.md` 和本计划的完成状态。

## 验收标准

- 主入口、转换入口、测试入口清晰。
- 不再依赖不可用的绝对路径配置。
- 重组后的代码可正常运行。
- 文档和目录职责清晰。
- 重要历史结论仍可追溯，但不要求保留原文件。
