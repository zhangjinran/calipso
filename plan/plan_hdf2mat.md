# 计划：HDF → MAT 转换验证评估

## 背景
当前流水线每次运行时都直接从 HDF5 文件读取 CALIPSO 数据。
将 HDF5 预处理为 `.mat` 数据库，有望提升效率、缩小体积、便于调试。

## 数据类型

流水线涉及 **3 类 CALIPSO 数据文件**，各自有不同的字段结构：

| 数据类型 | 产品 | 核心数据 |
|----------|------|---------|
| **APro** | 5km 气溶胶廓线 | 消光系数、后向散射、退偏比、AVD 分类、坐标、时间 |
| **VFM** | 垂直特征掩膜 | `Feature_Classification_Flags`（云/气溶胶/晴空分类） |
| **ALay** | 5km 气溶胶层 | `Column_TAOD_532`（总 AOD）、层顶/底高、坐标、时间 |

**三类文件的字段各自独立，需要分别评估、分别生成 MAT 库，不可混为一谈。**

## 执行步骤

### Step 1：写全量转换脚本 —— 1 天数据

写一个脚本 `hdf2mat_full.m`，功能：

```
对 1 个 HDF5 文件:
  1. hdfinfo() 获取所有数据集路径
  2. 遍历路径，hdfread() 读取每个数据集
  3. 全部写入 1 个 .mat 文件（v7.3 压缩）
  4. 计时、记录大小
```

分别对 APro / VFM / ALay 三类文件各执行一次。

**产出：** 3 个 MAT 文件 + 转换耗时/体积数据。

---

### Step 2：全量验证 —— 1 天数据

写一个脚本 `verify_full.m`，功能：

```
对每个 MAT 文件:
  1. load() 读取 MAT
  2. hdfread() 重新读取原始 HDF5 的同路径数据集
  3. 逐字段 isequal(HDF_val, MAT_val) ?
     ├─ 是 → 通过
     └─ 否 → max(abs(HDF_val - MAT_val)) < 1e-12 ?
         ├─ 是 → 精度损失可接受，通过
         └─ 否 → 转换 bug，修复后重测
```

**通过标准：** 所有字段通过。

---

### Step 3：效率 + 体积对比 —— 1 天数据

| 指标 | 对比方式 |
|------|---------|
| **读取速度** | `hdfread()` 读全部数据集 vs `load()` 读全量 MAT |
| **文件大小** | 原始 HDF5 vs 全量 MAT（.mat v7.3） |

**结论判定：**

| 全量 MAT 体积 | 验证通过 | 结论 |
|--------------|---------|------|
| ≤ HDF5 | ✅ | **直接用全量 MAT** |
| > HDF5 | ✅ | 进入 Step 4（精简 MAT） |
| 任意 | ❌ | 修 bug |

---

### Step 4：1 月数据最终验证

把 Step 1~3 扩展到 1 个月的数据量（如 2007-01-01 ~ 2007-01-31），验证在全量数据下效率和体积是否稳定。

---

### Step 5（按需）：精简 MAT

**仅当全量 MAT 体积 > HDF5 超标时才进入。**

1. 理清主函数实际使用的字段清单
2. 只保留这些字段生成精简 MAT
3. 用 `try/catch` 跑主函数，确认不缺字段
4. 对比精简 MAT 体积 vs HDF5

---

### Step 6：最终决策

```
全量 MAT 通过验证且体积不超标？
  ├─ 是 → 直接用全量 MAT，进入数据库组织设计
  └─ 否 → 精简 MAT 通过兼容测试且体积更小？
      ├─ 是 → 用精简 MAT
      └─ 否 → 放弃 HDF→MAT 转换，保持现状
```
