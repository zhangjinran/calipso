## 已知问题

### [已解决] `Properties` 字段读取失败

- **现象：** SDS 列表中存在 `Properties` 字段，`sd.readData()` 和 `hdfread()` 均无法读取
- **原因：** HDF4 维度表（dimension scale）或坐标变量，数据类型不被 MATLAB HDF4 接口支持
- **处理：** 跳过（每类产品丢失 1 个字段，不影响其他字段读取）
- **待办：** 如需读取，可在 Python 中使用 `pyhdf` / `h5py`

### [已解决] Vdata 读取不可用

- **现象：** `hdfh('open', ...)` → `hdfv('start', ...)` 接口无法初始化
- **原因：** MATLAB 当前版本的 HDF4 V 接口（hdfh/hdfv/hdfvs）不支持 CALIPSO 文件的 Vdata 读取
- **处理：** 跳过。科学数据均在 SDS 中，Vdata 仅为元数据
- **待办：** 如需读取，可在 Python 中处理

### [未解决] VFM 3 个文件转换失败

- **失败率：** 3/2511（0.12%）
- **原因：** 计时环节额外 `hdfread` 出错，非转换本身问题
- **影响：** 不影响其他文件的转换和验证

## 未完成 / 待办事项

### 1. 字段使用清单梳理 ⬜

**讨论背景（来自会话历史 turn 70-73）：**
- 当前是"全量转换"——即 HDF 中有多少字段就转多少
- 主函数实际用到的字段可能少于全量字段（有注释/删除/从未使用的字段）
- 后续计划做"部分转换"——只转主函数实际使用的字段
- **前提：** 需要全面梳理主函数及其被调用函数（如 `Fun_getCALIPSO_L2`、绘图脚本）中实际引用了哪些字段
- 梳理方法：搜索变量名在读取后的实际引用，排除被注释的、被删除的、从未使用的
- 三类产品（APro / ALay / VFM）都需要分别梳理

### 2. 树形目录结构重组 ⬜

**当前状态：** `month_test` 目录下 2511 个 MAT 文件散乱堆放在同一目录，无组织

**计划方案（详见 `plan_hdf2mat.md`）：**

### 3. 单日合并 MAT ⬜

- 当前每个 HDF 文件对应一个 `.mat` 文件（如 1 月有 2511 个 MAT）
- 计划将同一天同类型的所有 HDF 合并为一个 MAT 文件
- 日 MAT 内部结构：`day.meta`（转换元数据）+ `day.files{i}`（逐文件数据）

### 4. `database_index.mat` 索引账本 ⬜

- 轻量索引表，记录每个日期 MAT 的状态（complete / partial / failed）
- 支持查询：哪些日期转换失败？某月转换了多少文件？总体积多大？

### 5. 主函数集成 ⬜

- 修改主函数调用点：从 `hdfread()` 替换为 `load_day_data()`
- A 方案（改动小）：加载日 MAT 后拆成 cell，保持逐文件接口
- B 方案（改动大）：主函数直接批量处理一天数据

### 6. 增量更新机制 ⬜

- 检测逻辑：检查 `meta.status == 'complete'` 再跳过
- 防止"转换了 28/30 个文件就中断，残片 MAT 被当作已完成"

### 7. 与主流水线缓存机制的对接 ⬜

**注意：** `F:\AER_RETRA_CASE` 下的主流水线（`master_Chapter5_Fig5_1.m`）已经有一套自己的 build_log + 缓存机制（`output_integrated/build_log.mat`），hdf2mat 的产出需要和这套机制兼容。

## 结论

HDF → MAT 全量转换的 **可行性验证已通过**：

- ✅ 字段完整性 99%（仅 `Properties` 因 HDF4 类型不支持而跳过）
- ✅ 压缩比 13.6%（HDF 284 GB → MAT 38.9 GB）
- ✅ 读取加速 2~40 倍
- ✅ 失败率 0.12%（3/2511，均为计时环节问题，非转换本身）

**下一阶段：** 字段使用清单梳理 → 树形目录重组 → 主函数集成。
